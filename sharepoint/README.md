# SPFx web part — embed the CFA app *with* the signed-in user

The SharePoint **Embed** web part strips `<script>`, so it can't hand the logged-in user to the
iframe. This tiny **SPFx web part** runs *on the SharePoint page*, so it can read the current user
(no login) and pass it to the app. Use it **instead of** the Embed web part.

`CfaEmbedWebPart.ts` here is the only custom file. Everything else is generated by the official
SPFx toolchain (which pins the correct, tenant-compatible versions — that's why we don't hand-write
it). A SharePoint developer/admin does this once.

## Prerequisites
- **Node.js LTS** matching your SPFx version (SPFx 1.18 → Node 18; SPFx 1.21 → Node 22). If unsure,
  install **Node 18 LTS**.
- `npm install -g yo gulp-cli @microsoft/generator-sharepoint`

## 1. Generate the project skeleton
```bash
md cfa-spfx && cd cfa-spfx
yo @microsoft/sharepoint
```
Answer the prompts:
- Solution name: `cfa-embed`
- Component type: **WebPart**
- Web part name: **CfaEmbed**   ← use this exact name
- Framework: **No JavaScript framework**

## 2. Drop in the custom code
Replace the generated
`src/webparts/cfaEmbed/CfaEmbedWebPart.ts`
with the `CfaEmbedWebPart.ts` from this folder.

> Keep the generated `*.manifest.json`, `loc/`, and `config/` files as-is — they carry the unique
> component/solution GUIDs the toolchain created. Only the `.ts` is replaced.

If the generated `ICfaEmbedWebPartProps` interface lives in the manifest's `properties`, set sensible
defaults there (optional): `appUrl` = your app URL, `height` = `1000`.

## 3. Trust localhost certs (first time only) and test
```bash
gulp trust-dev-cert
gulp serve
```
It opens the SharePoint **workbench** — add the **CfaEmbed** web part, set the **App URL** in its
property pane, and confirm the app loads.

## 4. Package and deploy
```bash
gulp bundle --ship
gulp package-solution --ship
```
This produces `sharepoint/solution/cfa-embed.sppkg`. Then:
1. Go to your **tenant App Catalog** → *Apps for SharePoint* → **upload** the `.sppkg` → *Deploy*.
2. On the target site: **+ New → App** (or *Site contents → Add an app*) → add **cfa-embed**.
3. Edit the page → remove the old **Embed** web part → add the **CfaEmbed** web part → set **App URL**
   to `https://dynaautomation.pythonanywhere.com/` and **Height** to `1000` → **Republish**.

## How it works
- The web part reads `this.context.pageContext.user.displayName` (the signed-in user — no login) and
  loads the iframe as `…/?user=<name>`, and also `postMessage`s `{type:'cfa-user', user}` after load.
- The **app already reads both** (URL param `user` + that postMessage) on the `feature/operator-name`
  branch. So deploy the app from that branch (or merge it) for the name to be picked up and sent with
  each run.

## Notes
- Still keep `FRAME_ANCESTORS=https://dynatechconsultancy.sharepoint.com` set on the app so the iframe
  is allowed to render inside SharePoint.
- The user name is used for display/audit only; it is not a security boundary (SPFx passes what the
  page reports). If you later need a verified identity, that's Entra sign-in — a separate change.
